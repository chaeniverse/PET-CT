# PET-CT 저장소 리뷰 규칙

다발골수종 FDG PET/CT 병변 탐지 연구 저장소다. 코드·설정·문서만 두고 환자 데이터는 두지 않는다.
리뷰와 요약은 한국어로 쓴다. 규칙을 근거로 지적할 때는 "Rule 1" 처럼 번호를 붙인다.

## Rule 1. 데이터 보호 (가장 중요, 위반은 Critical)

- 환자 영상(`.dcm`·`.nii.gz`·`.mha`), 마스크, 임상자료(`.csv`·`.xlsx`), 모델 가중치(`.pth`), 가명 대응표가 커밋에 들어가면 지적한다.
- 환자 이름·등록번호·생년월일·검사 일시·원본 DICOM 폴더 이름이 코드 문자열·문서·로그 출력·주석에 들어가면 지적한다. 환자는 `P01`, `C001` 같은 가명으로만 쓴다.
- 환자에서 나온 파일(영상·수치표·그림)을 저장소 안 경로에 쓰는 코드는 지적한다. 결과는 `~/autopet3/` 아래에 둔다.
- 환자 파생물을 외부 주소(127.0.0.1·localhost 가 아닌 곳)로 보내는 코드는 지적한다. LLM 호출도 로컬 서버만 허용한다.

## Rule 2. 공개 코드 우선

- 병변 탐지·평가·미세조정·기준 SUV 계산을 직접 새로 구현하면 지적하고, 공개 저장소의 함수(nnU-Net, autoPET `val_script.py`, TCIA_processing, TotalSegmentator, autoDS-PET)를 쓰라고 제안한다.
- 직접 만든 코드는 시각화(후보 확인 페이지, Slicer 스크립트)와 데이터 연결(변환·전송)로 한정한다.
- `scripts/val_script.py`, `scripts/tcia_dicom_to_nifti.py` 는 공개 코드를 고치지 않고 복사한 파일이다. 이 두 파일에는 수정 제안을 하지 않는다.

## Rule 3. 문서를 같이 고친다

- 실행 절차·옵션이 바뀌었는데 `docs/guides/` 의 해당 가이드나 `docs/decisions.md` 가 같은 PR 에서 바뀌지 않았으면 지적한다.
- 문서는 한국어 짧은 평서문이다. 굵게(`**…**`)는 데이터 보호 경고에만 쓴다.

## Rule 4. PR 크기

- PR 하나는 변경 한 덩어리다. 커밋 1–5개, 바뀐 줄 대략 400줄 이하가 기준이다. 주제가 둘 이상 섞였으면 나누라고 제안한다.

## 낮은 우선순위로 볼 것

- 기존 파일과 같은 스타일의 린트 경고(긴 줄, shebang 실행 권한 등)는 지적하지 않는다.
- `env/*.lock.txt` 는 `uv pip freeze` 결과라 리뷰하지 않는다.
